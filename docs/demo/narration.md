# Demo narration — five minutes, keyed to the cast

This is the narration for the demo. No voice-over was recorded; the text
below is also published as closed captions in `narration.srt` and
`narration.vtt`, timed to a five-minute timeline at about 150 words a
minute, so a player can show it over the cast. It is written to be read out
loud in **five minutes**.

- `make-demo-n2.cast` — the live `make demo N=2` run, 1:35 of wall clock.
- `timings-20261013T000455Z-686422.cast` — the stored `N=4` timing table,
  reprinted, not a second live run.
- `make-demo-n2.txt` and `timings-*.txt` — the same runs as plain text, for
  anyone who would rather read than replay.
- `narration.srt`, `narration.vtt` — this script as closed captions,
  generated by `build-captions.py`. The `.srt` is what most players and
  YouTube accept; the `.vtt` is what an HTML5 `<video>` uses.

The script leads with the result, because that is what a viewer came for.
The terminal is evidence for the claims, not the subject.

**How to use the two clocks.** "Video" is the five-minute narration
timeline; "Cast" is a position inside `make-demo-n2.cast`. If you record a
voice-over, play the cast at 1x from the cast position and pause it whenever
the script says *hold* — the narration needs longer than the terminal does
for the segments that explain why a number matters. At 3:46 the visual
switches to the `N=4` timing cast. Pauses are expected; the terminal run is
real time, the narration is not.

Spoken text below is the block after each heading. Headings and the
instructions in this preamble are not read. The headings quote the caption
track's true cue times; run `python3 docs/demo/build-captions.py` after an
edit to re-time them and rebuild the captions.

---

## 0:00 — The result (cast: hold)

Four servers, powered off, on a bench. One command. Four and a half minutes
later they are a Slurm cluster that has just run a job on every one of them.
No console, no answer file, no manual step in the middle. That is the whole
claim, and everything after this is the machinery that makes it true.

## 0:24 — What the pipeline is (cast: hold)

Between a powered-off machine and a job there is a pipeline most people
never see: firmware, a DHCP offer on an isolated segment, a TFTP fetch, an
iPXE script, a kernel, an initramfs, a root filesystem that arrives over the
network, an identity that comes from somewhere other than the image, a
burn-in that gates the node, and a scheduler that has to be told the node
exists. This repository builds that pipeline and times every phase of it,
per node, every run. The timing is the deliverable, not a by-product.

## 1:02 — The command (cast 0:00)

Here is the run. `make demo N=2`: two nodes, from power-off to Slurm-ready.
`N` is a variable; nothing in the repository knows a node count. `platform-up`
is instant because the lab is already up — every step here is idempotent, so
a second run costs nothing and changes nothing. Then `converge` applies the
head node's configuration: the network, dnsmasq, NetBox, Warewulf, the
controller. That is fifty seconds, and it is flat in `N` — the check that no
per-node work leaked into a per-run step.

## 1:36 — The boot (cast 0:50)

At fifty seconds the nodes power on. Watch the phases. `node-define` creates
each disk and domain, `node-start` powers it on, then `firmware` — power-on
through UEFI and PXE. `dhcp-lease` is the first lease on the isolated
segment this boot; `ipxe` fetches the boot script; `kernel` and `initramfs`
pull the two early stages. `overlay` is the interesting one: the root
filesystem arrives over the network and the node's identity is layered on
top, so no two nodes share a filesystem. `login` is pivot to the real root
and systemd. Each number is measured live from the node's serial console,
per node, because firmware and iPXE print no timestamps of their own.

## 2:22 — Why the timing matters (cast: hold near 1:10)

Here is the result that matters. `platform-up` and `converge` stay flat as
`N` grows. `node-define` is almost linear and cheap. The contended phases
are the lease and the image fetch: one server answering every node at once.
At four nodes, `overlay` grows from about eight seconds to about twelve.
That bend is the scale argument, and it is a measured bend, not a guess.

## 2:48 — The gate (cast 1:20)

A login prompt is not a cluster. A fresh node arrives `staged`; it must pass
its own burn-in before it can take work, and the head node — not the node —
judges the result. On this run the gate is skipped in a tenth of a second:
these two already passed on an earlier run and NetBox already calls them
`active`. On the four-node run it takes a hundred and eighty-nine seconds,
because burn-in and the promotion reboots are per node and cannot be
parallelised away.

## 3:24 — Slurm (cast 1:20 to 1:35)

Then Slurm. `slurmd` starts with `--conf-server`; there is no `slurm.conf`
on a node, ever. Both nodes register and the job array runs one task per
node, all `COMPLETED`, exit zero. That is the finish line: the machines
took work. Ninety-five seconds of wall clock for this run, because the gate
was already satisfied.

## 3:46 — The same code at four nodes (cast: timings cast)

Now the same code at four nodes. This table is a reprint of a stored run,
so it is the real measurements, not a second live run. `converge` is fifty
seconds — flat. `nodes-up` is thirty-four and a half — slightly up. The gate
is a hundred and eighty-nine — linear in `N`, because burn-in is per node.
The job array is four seconds. Wall clock: two hundred and eighty-six
seconds, four minutes and forty-six, for four nodes. One command, no manual
step.

## 4:20 — What it does not prove (cast: hold on the table)

Three things it does not prove, stated on purpose. There is no InfiniBand
hardware; the RDMA numbers are Soft-RoCE over Ethernet, a real verbs data
path on an unreal fabric. There is no real BMC; Redfish power and boot order
are real, vendor BIOS attributes are not. And nothing above four nodes is
observed; the hundred-node claim is arithmetic over a measured per-node
cost, and it is labelled that way.

## 4:49 — Close (cast: hold)

The pipeline is code, every phase is a number, and nothing knows the node
count. That is the point.
